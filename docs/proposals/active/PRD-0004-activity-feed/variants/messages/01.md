# Message history / design 01

**Family:** [PRD-0004](../../README.md). **Status:** Proposed; original design pending.
**Reference:** [F2](../../../../initial-component-references.md#f2-spaced-message-feed), restricted inspiration only.
**Proposed implementation path:** `packages/pattern/src/activity-feed/messages/01.tsx`.

## Original composition

Readable actor/time metadata followed by a bounded message body and optional
attachments. Use original spacing and surface treatment to distinguish metadata
from content. Avoid reproducing the vendor's bubble, avatar and indicator layout.
The shared family contract does not imply a messaging backend.

## Requirements

- Plain text supports line breaks and long words. Links have meaningful labels;
  remote HTML is not injected. Bidirectional text is isolated where appropriate.
- Keep messages in caller order; do not group or hide actors based on assumptions
  about conversations. No sending, composer, threading or delivery receipts.
- A message surface is content, not an implicit button. Unread state is supplied
  by the caller and must not change just because the row is visible.
- Reuse actor/time/attachment semantics only where useful; retain local layout
  freedom rather than introducing a conditional universal feed component.

## Design-specific checks

Test paragraphs, code-like long tokens, links, RTL text inside LTR UI, many
attachments, missing names/images and loading more above/below current content.
Focus and scroll must stay stable. Apply [family acceptance](../../spec.md#acceptance)
including original-design review and all outstanding responsive/accessibility QA.
