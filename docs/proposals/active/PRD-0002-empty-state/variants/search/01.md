# Search recovery / design 01

**Family:** [PRD-0002](../../README.md). **Status:** Proposed; no implementation.
**Reference:** [E1](../../../../initial-component-references.md#e1-search-recovery-empty-state).
**Proposed implementation path:** `packages/pattern/src/empty-state/search/01.tsx`.

## Anatomy and original treatment

Small decorative search icon, heading, optional explanation, then actions. Use
the repository's own icon surface, spacing and theme tokens. A quiet container
must remain usable without media. Default copy in the showcase explains which
search produced no matches; product strings remain caller supplied.

## Requirements

- Provide a reset action and optional create action only when callbacks/links and
  permissions exist. The product decides which action is primary.
- Preserve input order when buttons wrap or stack. Long labels may wrap without
  losing hit area or focus outline. Do not force a fixed two-button row.
- Clearing a filter is a caller action. The example must demonstrate the updated
  result and where focus goes; the empty state does not invent search logic.
- Show no-results, no-action, pending reset and caller failure feedback fixtures.
  A failure message must not claim the reset succeeded.

## Design-specific checks

Inspect short and multi-line titles, long search terms, two long action labels,
keyboard activation, repeated reset while pending, and return to populated data.
Apply all [family acceptance](../../spec.md#acceptance). The source was desktop
reviewed; narrow layout and contrast are still pending for our implementation.
