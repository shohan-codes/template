# Icon and value / design 01

**Family:** [PRD-0006](../../README.md). **Status:** Provisional visual candidate; not implemented.
**Reference:** [M1](../../../../initial-component-references.md#m1-icon-and-value-metric).
**Proposed implementation path:** `packages/pattern/src/metric-card/icon-value/01.tsx`.

## Composition

One bounded metric surface with an optional icon, prominent formatted value,
clear label and optional explanatory period/description. Use semantic label/value
markup while visual layout may emphasize the value first. Icon start/end are
options of the same design and do not create separate files or state engines.

## Design requirements

- Use original repository-token styling rather than hard-coded source colors.
  The icon is subordinate to the value and may be omitted without a layout hole.
- Keep logical placement and reading order stable on mobile/RTL. Do not inherit
  the source's breakpoint-dependent visual icon reorder by accident.
- Large values can wrap or use an explicitly formatted abbreviation with full
  accessible text. Missing data has visible words, not an ambiguous dash alone.
- No trend arrow, percentage, comparison baseline or chart is introduced under
  this design. A card grid with dashboard controls belongs to a later Block.

## Verification

Apply [family acceptance](../../spec.md#acceptance). Include zero versus missing,
negative/localized values, large currencies, long labels, all state transitions,
no icon and both icon positions. Visual quality remains a required gate; prior
sample-width evidence is not production approval.
