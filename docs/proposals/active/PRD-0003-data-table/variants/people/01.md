# People table / design 01

**Family:** [PRD-0003](../../README.md). **Status:** Proposed; no implementation.
**Reference:** [T1](../../../../initial-component-references.md#t1-selectable-people-table).
**Proposed implementation path:** `packages/pattern/src/data-table/people/01.tsx`.

## Anatomy

Optional title/count header, selection column, person identity, text status,
role, email, team labels, explicitly named row actions and optional page footer.
People data is a useful default column recipe over the generic table contract,
not a hard-coded account schema or a second selection engine.

## Visual requirements

- Keep person name primary and handle secondary, aligned to a stable avatar box.
  Show initials or a neutral fallback when no cleared image is available.
- Use restrained header fill and row dividers, deliberate padding, visible
  selection/focus and text labels for status. Apply repository tokens rather than
  importing the vendor theme wholesale.
- Long names, email and team labels must remain readable. If a summary such as
  “+2” is shown, expose the hidden team names through an accessible affordance.
- Keep a horizontally scrollable semantic table initially. Avoid a visually
  hidden email column with no alternate way to access it.
- The count reflects caller data. Pagination uses real state, never “100 users”
  and ten fixture pages unless the fixture actually supplies them.

## State and extension examples

Provide a plain data/columns example, a custom identity cell, controlled selection,
a mock server page and a caller-owned edit/delete demonstration with explicit
success/failure. Destructive actions remain product-owned. Loading, refreshing,
no people, no results and error-with-stale-data are visibly distinct.

## Design-specific checks

Test pointer and keyboard checkbox use, header mixed state, sortable headers,
page boundaries, long email scrolling, action menus near container edges and
focus after caller removal. Apply all [family acceptance](../../spec.md#acceptance).
If MIT source is reused, retain its notice and record local changes; replacing
the vendor's portraits and theme does not remove its source-license obligations.
